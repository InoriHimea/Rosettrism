# 開發計畫目錄

每次開始開發前，必須先在本目錄建立一份以日期與主題命名的計畫文件，讓需求、實作階段、驗收與測試紀錄可以被追蹤。

## 命名規則

計畫檔名格式：

```text
.plan/YYYY-MM-DD-topic.md
```

範例：

```text
.plan/2026-06-05-lyrics-ai-scoring.md
```

建議：

- `YYYY-MM-DD` 使用開始規劃或開始開發的日期。
- `topic` 使用小寫英文、數字與連字號，簡短描述本次變更主題。
- 一次開發若包含多個獨立功能，應拆成多份 plan，避免單一文件過大或範圍不清。

## 使用流程

1. 複製 `.plan/TEMPLATE.md` 為新的時間命名 plan。
2. 先填寫背景、目標、非目標、風險與預計階段。
3. 開發時依階段更新 task checklist、測試紀錄與完成狀態。
4. 若需求有追加或版本化紀錄，於 `requirement.md` 新增對應章節，並在 plan 中填入關聯需求或版本。
5. 完成後確認驗收條件與測試紀錄已更新，再進行 commit、tag 或 release 流程。
